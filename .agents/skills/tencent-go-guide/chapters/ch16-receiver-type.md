# 第 16 章: 接收器类型

## Core Idea
值还是指针接收器取决于**方法集语义与可复制性**，不取决于性能猜测；有疑问用指针；同一类型的方法全部统一为一种。

## Frameworks Introduced
按接收者类型与方法的决策清单：
- **切片 + 方法不重切片/重分配** → 值（`func (b Buffer) Len() int`）。
- **方法要修改接收者** → 必须指针（`func (c *Counter) Inc()`、`func (q *Queue) Push(x Item)`）。
- **含不可安全复制字段的结构**（`sync.Mutex` 等同步类型）→ 指针。复制安全性可查类型 Godoc。
- **大型结构/数组** → 指针可能更高效，但性能考虑不应凌驾可读性与正确性；真要优化先做基准测试。
- **与其他修改接收者的函数并发调用的方法**：修改对本方法不可见 → 值；否则指针。
- **结构体/数组含指向可变内容的指针字段** → 指针接收器，向读者明示可变性意图（`c.m.Add(1)`）。
- **内置类型（int/string）不修改** → 值（`type User string; func (u User) String()`）。
- **映射、函数、通道** → 值（它们本身是引用类型；`func (h Header) Add(...)`，见 net/http#Header）。
- **小的值类型**（无可变字段无指针，如 `time.Time`）→ 值（`func (t Time) Add(d Duration) Time` 返回新值）。
- **有疑问时** → 指针接收器。
- **一致性总则**: 同一类型的方法最好全部指针或全部值，保持方法集一致。

## Key Takeaways
1. 修改接收者、含 Mutex、含可变指针字段 → 指针；map/chan/func、小值类型、不重切片的切片 → 值。
2. 犹豫就指针，但同一类型所有方法保持一致。
3. 性能差异靠 benchmark 说话，不靠猜。
